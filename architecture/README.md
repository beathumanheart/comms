# Communication architecture

The model the external comms team agreed on. It names **roles, not people**, so it can be reused when team members rotate. People for the current season: [who to ask this season](../seasons/2026-27/owners.md).

Original slides: [Communication_Architecture_v4.pdf](Communication_Architecture_v4.pdf). This page is the same content as editable text — when the model changes, edit here.

## 1. One learning community, three roles

The educational project is shared; the legal entities remain distinct.

```roles
Descalças | cooperative | terrain · funding · partnerships
Learning Community | Bosque Escola + Planeta Alecrim | education · families · learning
Planeta Alecrim | association | Beirã Station
```

Two familiar places for families: **Quinta das Avelãs** and **Beirã Station**.

## 2. Every channel has a job

Shared education; separate organisational voices and responsibilities.

| | Learning Community | Descalças | Planeta Alecrim |
|---|---|---|---|
| What it is | Comunidade de Aprendizagem: Bosque Escola + Planeta Alecrim | Cooperative | Association — separate legal entity |
| Speaks about | Education · families · learning | Terrain · funding · partnerships · projects | Its Beirã Station contribution |
| Voice | The shared learning story | Institutional | Its own channels and content |

Association and cooperative channels remain separately accountable. The full list of channels is in [the channel list](../channels.md).

**Shared content system:** media assets and the archive live in Google Drive; the editorial calendar, rules and evidence log live in this space.

## 3. From posting to purpose

Five content pillars — every post belongs to one:

| # | Pillar | The question it answers |
|---|---|---|
| 1 | **Life** | What happens here? |
| 2 | **Learning** | What are we learning? |
| 3 | **People** | Children · families · educators |
| 4 | **Community** | Territory · ecology · culture |
| 5 | **Opportunities** | Join · visit · volunteer |

Every campaign starts with: **Audience → Objective → Message → Action.**

## 4. A clear route to publish

One continuous path, with one named owner at each handoff.

```flow
Activity | school · project · event
Capture | photos · facts · context
Shape · Check · Approve | story · consent · accuracy
Publish + Archive | channel · record · evidence
```

**Exception:** small local initiatives can remain informal and outside the main channels.

## 5. Visibility is a project task

For funded projects (CES, Enraizar / Alentejo 2030, others), Descalças checks the requirements and keeps the evidence.

```flow
Verify | actual agreement
Prepare | wording · logos
Publish | approved channels
Prove | links · screenshots
Report | evidence ready
```

**Rule:** confirm every visibility obligation against the actual project agreement. Working pages: [funded projects](../funded-projects/).

## 6. Make evidence routine

Build the publication record as work happens, not at the reporting deadline.

| When | What |
|---|---|
| Now | Audit channels |
| On arrival | Brief volunteers |
| Each activity | Capture facts |
| Monthly | Publish |
| Ongoing | Archive proof |
| Reporting deadline | Report ready |

**Handoff:** volunteers supply stories and facts → communications publishes → Descalças checks evidence.

## 7. Make the model operational

1. **Confirm** legal relationships and leadership
2. **Assign** one owner and purpose per channel
3. **Define** content ownership and sign-off
4. **Verify** CES / Enraizar agreement requirements
5. **Record** decisions in an accessible shared space
